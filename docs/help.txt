HELP PANE

QUICK START

Selectoscope is a visual tool that lets you explore network structure through linked interpretable views. Select nodes and/or edges from the visual pattern in one pane to examine the same selection set in other panes.

The interface has three parts. The top control strip has selection set choice (node sets, edge sets, or both), a report of selection counts, choice of brush modality, and controls that grow or shrink sets. Then the primary view, or the main middle view, is composed of panes that show the same network dataset in various ways, surfacing different yet interpretable visual patterns. Finally, the bottom control strip is dynamic, changing offered controls in response to the focused pane.

Consider these steps as a quick start:

1. Change the loaded data from the DATA pane, which can be toggled back from this HELP pane by clicking the ? button.
2. Drag in any pane to brush a selection area around a visual pattern that catches your eye.
3. Then look across to other panes, the same nodes light up blue and edges orange, wherever they sit.
4. Click ▲ in EXTEND SET to grow your selection by one hop, and see how far the selection spreads.
5. Run AUTO SWEEP at the bottom control strip to scan an animated selection band area across the vertical span of the pane, then watch the selection across every other pane.
6. Hover the SELECTION COUNT in the top control strip and click CLEAR to start over, or lasso an empty region in any pane.

Click ? to come back to this HELP pane at any time.

PANES

Each pane draws the same loaded network in its own way. Here is what each pane shows, and what its bottom control strip offers.

DATA + HELP PANE

In the DATA pane, click a dataset from the list to load it, replacing the already loaded dataset. Loading a fresh dataset also clears any node or edge selection set. The bottom control strip then serves that dataset: its export, and for your own data its files (see UPLOADED below).

Turn on THUMBNAILS to see a NODELINK preview of the dataset's BESPOKE 2D layout, or else the default force-directed 2D, with edges only.

Click ? in the pane's header, or at the left corner of the bottom control strip, to switch between the DATA pane and this HELP pane.

In the HELP pane, turn off FIGURES to hide the diagrams and control copies, leaving the text alone.

LABELS PANE

One row per node, where rows selected are automatically sorted to the top for visibility, once the pointer leaves the list.
Select nodes with the same operations as the other panes: hover to highlight, click a row to select or unselect a node row, drag to select many contiguous node rows (Alt or Option to remove from the selection set).

Sort the vertical order of rows by:

LABELS (A–Z) for an alphabetical sort, ignoring case, with numbers in numeric order, and unlabeled nodes last.

DEGREE for a sort based on degree centrality, or how many neighbors each node has, the most first. Degree is also the tie-breaker in the other numeric sorts.

ONION for a sort based on the onion decomposition, or how deep a node sits in the graph's density gradient: the later a peeling of the least-connected nodes removes the node at hand, the higher its onion value. The deepest nodes come first.

EIGENVECTOR for a sort based on eigenvector centrality, or how well connected a node's neighbors are, counted recursively, the highest first.

Every sort but LABELS (A–Z) shows each node's value in a column between its number and its label: whole numbers for DEGREE and ONION, three decimals for EIGENVECTOR. When the pane is narrow, the node number hides first, so the value and the label keep the room.

NODELINK PANE

Nodes are points and edges are lines that link connected node pairs, a familiar and intuitive visual representation of network structure. For selection, a drawn area takes the node points inside it in NODES mode, the edges they share in EDGES mode, and both in BOTH mode.

Layout: All datasets can be shown with a standard force-directed 2D, seeded by the first two harmonics of the spectral eigendecomposition (see MATRIX PANE description below). Similarly, a force-directed 3D, seeded by the first three harmonics, is computed last for datasets that don't bring their own 3D layout; for those that do, click COMPUTE 3D LAYOUT in the 3D layout. Datasets can bring their own layouts: BESPOKE 2D shows the dataset's own 2D layout, and BESPOKE 3D shows the dataset's own 3D layout.

Toggle INTERACTIVE mode on to start a force-directed simulation from the current layout. In INTERACTIVE mode nodes can be moved by dragging. Because of computing cost, INTERACTIVE mode is unavailable for datasets above 6000 nodes or 20000 edges.

MATRIX PANE

This pane surfaces visual patterns from matrix seriation, or the symmetric ordering of nodes along the side of the matrix. For selection, a drawn area takes the edge points inside it: in EDGES mode the edge points directly, in NODES mode their endpoint nodes, and in BOTH the two modes act together.

Layout: The visual idiom is the classic Adjacency Matrix, where edges are points, and their respective nodes drawn as lines along rows and columns. By default the matrix is shown as a DIAMOND with the diagonal running vertically, though the traditional SQUARE view is also available.

The visual pattern surfaced by edge points can reveal positional or structural information about nodes. We use spectral seriation to capture positional information, or where in the topology two nodes are; and Principal Component Analysis (PCA) seriation to capture structural information, or how similar the neighborhoods of two nodes are.

For positional information: the H1, H2 and H3 diagonal orders are the first three harmonics of the graph's Laplacian, smoothest first. Each spectral harmonic places linked nodes close in the visual pattern. The first harmonic is H1, which surfaces a visual pattern that results from the node ordering following the Fiedler eigenvector, the smoothest harmonic. The next harmonics are H2 and H3 (no eponyms), each orthogonal to all previous harmonics.

For structural information: the PC1, PC2 and PC3 diagonal orders come from the PCA of the nodes' neighborhoods. Each PC places nodes with similar neighborhoods close, whether or not they are linked. The first PC is PC1, which explains the most variance: the diagonal polar ends, or the extremes of the visual pattern, surface the strongest contrast between neighborhoods. Next are PC2 and PC3, which explain the next most variance, each orthogonal to the PCs before them.

CORES PANE

This pane is about the graph's density. For selection, a drawn area takes the node points inside it in NODES mode, while edges are drawn only when selected, as orange chords; or hovered, as a red chord. These chords can't be clicked, but a drawn area in EDGES or BOTH mode does select the edges between the nodes it covers.

Layout: A new visual idiom we call kSnakes, where nodes are points that are vertically placed according to k-core shell membership (reported as text on the right side of the pane), which maps height to the depth into the graph's dense core. Nodes in the densest core are at the top, while nodes in the sparse periphery are at the bottom. Within each k-core shell, the onion decomposition (numbers on the left) sets every node's height, which creates snake-like visual patterns. Node points are drawn within an enclosure if they are part of the same connected component within that k-core shell.

The horizontal order of connected components can be by:

TOP-DOWN places each component at the mean horizontal position of its neighbors in denser shells, nearer shells counting more, so components that connect across shells line up, a layout that results from reducing edge crossings.

SIZE packs components within a k-core shell horizontally from sparse to dense: by a component's highest onion value, then by its total onion value, then its size in number of nodes, arranged from left to right.

The aspect ratio of the visual pattern can be adjusted with the SPACING slider. The vertical GRIDLINES that bin component locations for horizontal TOP-DOWN or SIZE ordering can be made visible as well.

Sometimes a k-core shell can have many singleton nodes, which can make the visual pattern crowded. Singletons are bare node points with no enclosure, placed vertically according to their onion value. The GROUP SINGLETONS toggle collects singletons within a k-core shell, holding one enclosure per onion value that aggregates and counts all of its singletons.

HOPS PANE

This pane is about the graph's eccentricity. It shows a new visual idiom we call HopCensus, where nodes are represented by polylines. For selection, a drawn area takes any overlapping node polylines in NODES mode. Edges are never drawn in this pane, but EDGES and BOTH modes take the edges between the polylines the area covers.

Layout: A polyline is drawn from a vector of integers in a shared coordinate system: stubs (edge ends) met for the first time at each hop from the node, starting from its degree at hop 0, until the whole graph is traversed. The shape of the polyline comes from the varying stub counts, while the traversal extent in hops maps to the length of polyline, or the node's eccentricity (reported as text on the right side of the pane). In the vertical span of the pane, the most central nodes are at the top (shortest polyline lengths, the radius nodes), while the nodes on the graph's perimeter are at the bottom (longest polyline lengths, the diameter endpoint nodes).

The SPACING slider sets how far the polylines move horizontally, following a chosen ordering by polyline wave shape:

DEGREE moves to the left polylines that start high (large degree), and those that start low right (low degree). In %, the share of the graph's stubs met at hop 0, which is the polyline's first value.

REACH moves to the left waves whose bulk shape arrives in a few hops, and those whose bulk occurs late right. In %, the wave's mean hop, its centre of mass, as a share of its length.

SPREAD moves to the left polylines whose wave shapes spread over many of their hops, and moves to the right polyline shapes that form a tight wave. In %, the wave's standard deviation in hops as a share of its length.

SKEW moves to the left wave shapes whose bulk arrives early and trails off in a long tail, and moves to the right polylines that climb for long and end abruptly. In %, how much further the wave's last tenth of stubs lies past its mean hop than its first tenth lies before it, as a share of its length.

The RANKING toggle converts each set of equal values into one evenly spaced column (so twins share one). When off, each polyline sits at its numeric value, so gaps and outliers show.

AUTO SWEEP

Click RUN in a pane's bottom control strip to animate a band across the pane, lighting what it covers in every pane. While a sweep is active, BRUSH and EXTEND SET are inactive, and the SELECTION COUNT follows the band. Press ↓ or → to step forward and ↑ or ← to step back. Hold to keep it moving.

A step pauses the sweep; click RESUME to carry on.

Turn off VERTICAL to sweep left to right. The AREA setting sets how much of the pane the band covers, while SPEED sets how fast the band travels.

Click STOP, or change the selection by drawing an area, clicking an item, or loading a dataset, to end the sweep. In contrast, general navigation like zooming, panning and rotating within panes does not stop an active sweep.

UPLOADED

Your own networks sit at the top of the DATA pane, under UPLOADED, newest first, for as long as the page stays open. Everything is computed in your browser, and your files never leave it.

Click + NEW at the top of UPLOADED, or in ADD DATASET, to upload your own data: it takes the ring, and the bottom control strip turns to UPLOAD YOUR DATA. Choose BUILD FROM CSV to build a dataset from your own CSV files, computed in your browser, or UPLOAD FROM JSON to open a build file saved by EXPORT, without computing anything.

With BUILD FROM CSV, add an edge list with + EDGELIST, type a NAME if you like, and click ADD to add the dataset to UPLOADED and show it. Once your edge list is read, its row takes the ring and the bottom control strip, and each pane fades in as its part of the build finishes; the force-directed 3D layout comes last. Click STOP to stop the build; the row keeps what has landed.

An edge list is a CSV file with a header row and the columns source and target, one edge per row; any other column is ignored. Each node is named by its node_id, exactly as written in the file. Up to 10000 nodes and 100000 edges are supported.

Once your dataset is built, CHANGE in the bottom control strip shows which files it has and which it lacks, and adds files that join on node_id: LABELS (node_id,label), BESPOKE 2D (node_id,x,y) and BESPOKE 3D (node_id,x,y,z). A pane with nothing to show for want of one offers the same file under its message. Matching their node_id values to the edge list is up to you: a file with a node_id the edge list never names or a repeated node_id is refused whole, with counts, and everything else still loads. A layout must place every node; labels may cover only some, and the report counts the nodes left unlabeled.

Your edge list is cleaned rather than refused, and the report says what changed: direction is ignored, self-loops are dropped, repeated edges are merged, and only the largest connected component is kept.

Red, the colour of a hovered item, also marks whatever stopped your data loading: a refused file, a part of the build that failed, or a file that could not be read. Rest the pointer on a file to read its report: why it was refused, then what cleaning changed. Hover a file to REPLACE the edge list, or to REMOVE any other file.

Click one of your rows to bring its CHANGE back to the bottom control strip: replacing the edge list, or adding or removing another file, builds it again at once. Click REMOVE in DATASET to take the row off the list.

A curated dataset shows its download on its own row in the DATA pane; if a download fails, the row reads failed, and clicking it tries again. If the list of datasets can't be read, click RETRY to try the download again.

Click EXPORT JSON in DATASET to save a finished dataset as one build file. To open it again, click + NEW and choose UPLOAD FROM JSON: + DATASET takes a build file saved by EXPORT and reads it at once, refusing a file that is not a build. Name it if you like, and click ADD to open it as a new row. The precomputed samples in the list are such builds of their own CSV files.

CONTROL STRIPS

Rest the pointer on a tray of controls in either control strip to read what it does, in these words.

TOP CONTROL STRIP

SELECTION SET chooses whether a drawn area takes NODES, EDGES or BOTH.
SELECTION COUNT shows how much of the graph each set holds; hover it and click CLEAR to empty the selection set.
BRUSH chooses a RECTANGLE or a LASSO as the modality for the drawn selection.

EVERY PANE'S BOTTOM CONTROL STRIP

ZOOM: − and + zoom the pane out and in; click the % to fit the visual pattern into the pane.
AUTO SWEEP: click RUN to animate a band across the pane, lighting what it covers in every pane. STOP ends the sweep, and RESUME carries on a paused sweep.
SWEEP CONTROLS shape the band: VERTICAL sets its direction, AREA how much of the pane it covers, SPEED how fast it travels, and ARROW steps it, as the arrow keys do. They work only while a sweep is active.

HOPS PANE

HORIZONTAL WAVE ORDER BY orders the polylines by wave shape, by DEGREE, REACH, SPREAD or SKEW; SPACING sets how far they move horizontally, and RANKING sets each set of equal values in one evenly spaced column.
