QUICK START

Selectoscope is a visual tool that lets you explore network structure through linked interpretable views. Select nodes and/or edges from the visual pattern in one pane to examine the same selection set in other panes.

The interface has three parts. The top control strip has selection set choice (node sets, edge sets, or both), a report of selection counts, choice of brush modality, and controls that grow or shrink sets. Then the main section is composed of horizontally juxtaposed panes that show the same network dataset in various ways, surfacing different yet interpretable visual patterns. Finally, the bottom control strip is dynamic, changing the controls offered in response to the focused pane.

Consider these steps as a quick start:

1. Change the loaded data from the DATA pane, which can be toggled back from this HELP pane by clicking the ? button.
2. Drag in any pane to brush a selection area around a visual pattern that catches your eye.
3. Then look across to other panes, the same nodes light up blue and edges orange, wherever they sit.
4. Click ▲ in EXTEND SET to grow your selection by one hop, and see how far the selection spreads.
5. Hover the SELECTION COUNT in the top control strip and click CLEAR to start over, or lasso an empty region in any pane.
6. Run AUTO SWEEP at the bottom control strip to scan an animated selection band area across the vertical span of the pane, then watch the selection across every other pane.

Click ? to come back to this HELP pane at any time.

SELECTION CONTROLS

Each color shows in every pane. Hover an item to light it red everywhere.

Edge set: the edges you picked
Hovered item: under your pointer

With BRUSH choose a modality for the drawn selection.
Hold Shift while dragging to add to the selection, or Alt (Windows) or Option (MacOS) to remove.

Choose in SELECTION SET whether a drawn area takes NODES, EDGES or BOTH. In a pane with only node items, EDGES mode takes the edges between the nodes inside the drawn area.

PANES

Each pane draws the same loaded network in its own way. Here is what each pane shows, and what its bottom control strip offers.

DATA + HELP PANE

In the DATA pane, click a dataset from the list to load it, replacing the already loaded dataset. Loading a fresh dataset also clears any node or edge selection set. The bottom control strip then serves that dataset: its export, and for your own data its files (see USING YOUR OWN DATA below).

Turn on THUMBNAILS to see a NODELINK edges-only preview of the dataset's BESPOKE 2D view when the layout is available, else falls back to the force-directed 2D layout.

Click ? in the pane's header, or at the left corner of the bottom control strip, to switch between the DATA pane and this HELP pane.

LABELS PANE

One row per node, where rows selected are automatically sorted to the top for visibility, once the pointer leaves the list.
Select nodes with the same operations as the other panes: hover to highlight, click a row to select or unselect a node row, drag to select many contiguous node rows (Alt or Option to remove from the selection set).

Sort the vertical order of rows by:

LABELS (A–Z) for an alphabetical sort, ignoring case, with numbers in numeric order, and unlabeled nodes last.

DEGREE for a sort based on degree centrality, or how many neighbors each node has, the most first. Degree is also the tie-breaker in the other numeric sorts.

ONION for a sort based on the onion decomposition, or how deep a node sits in the graph's density gradient: the later a peeling of the least-connected nodes removes the node at hand, the higher its onion value.

EIGENVECTOR for a sort based on eigenvector centrality directly from the Adjacency matrix, or how well connected a node's neighbors are, the highest first.

Every sort but LABELS (A–Z) shows each node's value in a column between its number and its label: whole numbers for DEGREE and ONION, three decimals for EIGENVECTOR. When the pane is narrow, the node number hides first, so the value and the label keep the room.

NODELINK PANE

Nodes are points and edges are lines that link connected node pairs, a familiar and intuitive visual representation of network structure. For selection, a drawn area takes the node points inside in NODES mode, the edges they share in EDGES mode, and both in BOTH mode.

Layout: All datasets can be shown with a standard force-directed 2D layout, seeded by the first two harmonics of the spectral eigendecomposition (see MATRIX PANE description below). Similarly, a force-directed 3D layout, seeded by the first three harmonics, can be computed on demand. Additionally, datasets can have their own bespoke layouts, shown with BESPOKE 2D and BESPOKE 3D when available.

Toggle INTERACTIVE mode to start a force-directed simulation from the current layout. In INTERACTIVE mode nodes can be moved by dragging. Because of runtime computing cost, INTERACTIVE mode is unavailable for datasets above 6000 nodes or 20000 edges.

MATRIX PANE

This pane surfaces visual patterns from matrix seriation, or the symmetric ordering of nodes along the side of the matrix. For selection, a drawn area takes the edge points inside it: in EDGES mode the edge points directly, in NODES mode their endpoint nodes, and in BOTH the two modes act together.

Layout: The visual idiom is the classic Adjacency Matrix, where edges are points, and their respective nodes drawn as lines along rows and columns. By default the matrix is shown as a DIAMOND with the diagonal running vertically, though the traditional SQUARE view is also available.

The visual pattern surfaced by edge points can reveal positional or structural information about nodes. We use spectral seriation to capture positional information, or where in the topology two nodes are; and Principal Component Analysis (PCA) seriation to capture structural information, or how similar the neighborhoods of two nodes are.

For positional information: the H1, H2 and H3 diagonal orders are the first three harmonics of the graph's Laplacian, smoothest first. Each spectral harmonic places linked nodes close in the visual pattern. The first harmonic is H1, which surfaces a visual pattern that results from the node ordering following the Fiedler eigenvector, the smoothest harmonic. The next harmonics are H2 and H3 (no eponyms), each orthogonal to all previous harmonics.

For structural information: the PC1, PC2 and PC3 diagonal orders come from the PCA of the nodes' neighborhoods. Each PC places nodes with similar neighborhoods close, whether or not they are linked. The first PC is PC1, which explains the most variance: the diagonal polar ends, or the extremes of the visual pattern, surface the strongest contrast between neighborhoods. Next are PC2 and PC3, which explain the next most variance, each orthogonal to the PCs before them.

Every diagonal order starts from its denser pole, with the higher mean degree facing the top of the pane.

SHELLS PANE

This pane shows how density varies within the graph. Density is a measure of edge saturation, or how connected a group of nodes are to each other, from sparse (least density) to complete (most density). For selection, a drawn area takes the node points inside it in NODES mode, while edges are drawn only when selected, as orange chords; or hovered, as a red chord. These chords can't be clicked, but a drawn area in EDGES or BOTH mode does select the edges between the nodes it covers.

Layout: A new visual idiom we call kSnakes, where nodes are points that are vertically placed according to k-core shell membership (reported as text on the right side of the pane), which maps height to the depth into the graph's dense core. Nodes in the densest core are at the top, while nodes in the sparse periphery are at the bottom. Within each k-core shell, the onion decomposition (numbers on the left) sets every node's height, which creates snake-like visual patterns. Node points are drawn within an enclosure if they are part of the same connected component within that k-core shell.

The horizontal order of connected components can be by:

SIZE packs components within a k-core shell horizontally from sparse to dense: by a component's highest onion value, then by its total onion value, then its size in number of nodes, arranged from left to right.

BARYCENTER places each component at the barycenter, or mean horizontal position, of its neighbors in denser shells, nearer shells counting more, so components that connect across shells line up, a layout that results from reducing edge crossings.

The aspect ratio of the visual pattern can be adjusted with the SPACING slider. The vertical GRIDLINES that bin component locations for horizontal SIZE or BARYCENTER ordering can be made visible as well.

Sometimes a k-core shell can have many singleton nodes, which can make the visual pattern crowded. Singletons are bare node points with no enclosure, placed vertically according to their onion value. The GROUP SINGLETONS toggle collects singletons within a k-core shell, holding one enclosure per onion value that aggregates and counts all of its singletons. A group's enclosure acts as all its singletons: hovering lights them all, a click selects them all, and once some are selected it reads selected over total.

HOPS PANE

This pane shows how eccentricity varies within the graph. Eccentricity is the distance in hops a given node is from its furthest reachable nodes, from central nodes (low eccentricity) to peripheral nodes (high eccentricity). For selection, a drawn area takes any overlapping node polylines in NODES mode. Edges are never drawn in this pane, but EDGES and BOTH modes take the edges between the polylines the area covers.

Layout: Shown is a new visual idiom we call HopCensus, where each node is visually encoded by a polyline. A polyline is drawn from a vector of integers in a shared coordinate system: stubs (edge ends) met for the first time at each hop from the node, starting from its degree at hop 0, until the whole graph is traversed. The shape of the polyline comes from the varying stub counts, while the traversal extent in hops maps to the length of polyline, or the node's eccentricity (reported as text on the right side of the pane). Locally, polylines are drawn within a unit square, all share the same vertical scale; the tallest and longest set the relative extremes within the unit square. In the overall vertical span of the pane, the most central nodes are at the top (shortest polyline lengths, the radius nodes), while the nodes on the graph's perimeter are at the bottom (longest polyline lengths, the diameter endpoint nodes).

The SPACING slider sets how far the polylines move horizontally, following a chosen ordering by polyline shape similarity:

DEGREE is a measure of degree centrality in percent, or the number of neighbor nodes a given node has, divided by the number of other nodes (node count minus one). The first value of a polyline is the node's degree, the stubs met at hop 0. Polylines that start high (large degree) move to the left, while polylines that start low (small degree) move to the right.

REACH is a measure of where the mean of the polyline shape is, in terms of hops. Polyline shapes with a small mean hop move to the left, while shapes with a large mean hop move to the right. In percent, the mean hop, as a share of length in hops.

SPREAD is a measure of how much of the polyline shape spreads horizontally over hops. Polyline shapes that spread over many hops move to the left, while polylines that have a narrow peak move to the right. In percent, the standard deviation of the polyline in hops, as a share of length in hops.

SKEW is a measure of how much of the polyline shape exists before or after the mean hop. Polylines whose bulk shape occurs in early hops and trail off in a long tail move to the left, while a polyline shape that starts shallow and climbs later moves to the right. In percent, how much further the polyline's last tenth of stubs lies past its mean hop, versus its first tenth lies before the mean hop, as a share of length in hops.

The RANKING toggle places polyline shapes following an evenly spaced horizontal ranking, with polylines of equal values superimposed. When off, each polyline sits at its numeric value, so gaps and outliers show.

AUTO SWEEP

Click RUN in a pane's bottom control strip to animate a band across the pane, lighting what it covers in every pane. The band lights what a drawn area would take in the current SELECTION SET mode, so a sweep previews a selection.

While a sweep is active, BRUSH and EXTEND SET are inactive, and the SELECTION COUNT follows the band. Press ↓ or → to step forward and ↑ or ← to step back. Hold to keep it moving. A step pauses the sweep; click RESUME to carry on.

Click STOP, or change the selection by drawing an area, clicking an item, or loading a dataset, to end the sweep. In contrast, general navigation like zooming, panning and rotating within panes does not stop an active sweep.

Turn off VERTICAL to sweep left to right. The AREA setting sets how much of the pane the band covers, while SPEED sets how fast the band travels.

USING YOUR OWN DATA

Click the +NEW row in the DATA pane to add your own network data. Choose BUILD FROM CSV to create a dataset from an edgelist, or UPLOAD FROM JSON to open a previously built and exported SELECTOSCOPE dataset. All processing happens in your browser, and your files never leave it. Selectoscope supports up to 10,000 nodes and 100,000 edges.

To build a dataset, the main file format is the EDGELIST, a CSV file with 'source' and 'target' columns, one edge per row. Column names can be in any case ('Source' reads as 'source'). Nodes must match across CSVs under a 'node_id' column, where values are treated as plain trimmed strings. Can be any text, but must match exactly across EDGELIST, LABELS, BESPOKE 2D, and BESPOKE 3D files. For example, "1" and "01" count as different 'node_id' entries.

Selectoscope automatically cleans the EDGELIST information: edge direction is ignored, self-loops are removed, duplicate edges are merged, and only the largest connected component is kept. Click ADD to build.

Per dataset built through CSV, optional files must use the 'node_id' column and match the EDGELIST. There are three optional CSV files to upload. The BESPOKE 2D layout requires 'node_id', 'x', and 'y' columns, and BESPOKE 3D requires 'node_id', 'x', 'y', and 'z' columns, both of which must account for every node in EDGELIST. The LABELS requires 'node_id' and 'label' columns, and in contrast to the bespoke layouts, labels can be partial.

Once built, the options in CHANGE can add, replace, or remove files; and click EXPORT CSV to save the built CSV files.

Click EXPORT JSON to save a built dataset as a single file. Reopen the dataset through +NEW and UPLOAD FROM JSON, without rebuilding.
